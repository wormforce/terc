# terc 使用说明

`terc` 是 Mihomo（Clash.Meta）的终端控制器，支持 **macOS** 和 **Linux**。打开之后直接进入面板。已经有配置时，不会再经过启动菜单。

界面默认是简体中文。按 `s` 可以改成 English 或 日本語。

## 第一次打开

满足下面三条时，启动后先出现「初始设置」，而不是面板：

- 还没有保存机场订阅链接
- 本机 Mihomo 没在运行
- 配置目录里还没有 `config.yaml`

已经有其中任意一项，就直接进入面板。

初始设置做三件事：

1. 先确认 `mihomo` 内核已安装。没有的话按 `Ctrl+D`，从 GitHub 上的 MetaCubeX/mihomo 下载和这台机器匹配的包，放到 `~/.config/terc/core/mihomo`。
2. 粘贴机场给你的订阅链接，按 Enter。链接要以 `http://` 或 `https://` 开头，保存在本机 `~/.config/terc/config.json`；下载的配置会先由内核验证。没有机场也可以：直接粘贴一条自己的节点（Surge 节点行或 `ss://` 等链接，见「代理订阅与分流方案」），terc 会保存为结构化代理记录并生成配置。
3. 订阅写好、二进制也在，就会启动内核。

按 `Esc` 可以先关掉这个窗口。之后从设置 → 订阅与分流 → 添加代理重新打开。

系统代理不会在这一步打开。确认网络正常后，再在面板上按空格手动接管。

下载的内核包按本机选择，只有这四种：

| 系统 | CPU | 包名 |
| --- | --- | --- |
| macOS | Apple 芯片 | `mihomo-darwin-arm64` |
| macOS | Intel | `mihomo-darwin-amd64-v1` |
| Linux | arm64 | `mihomo-linux-arm64` |
| Linux | x86_64 | `mihomo-linux-amd64-v1` |

不提供 Windows 包。x86_64 用 `-v1` 基础版：不带后缀的 `amd64` 包要求 AVX2，老 CPU 和部分虚拟机跑不起来。

下载先读最新版的 `version.txt`，再按版本号取对应文件，不经过 api.github.com，所以不受它每小时 60 次的限制。速度连续 60 秒低于 1 KB/s 才算卡住，卡住就重试，并从已下载的部分续传；慢速网络只要还在走，就会一直下完。失败时通知里带上 curl 的原因。内核正在运行且没开 TUN 时，先经内核自己的本地端口（`127.0.0.1` 的混合端口或 HTTP 端口）下载，不通再直连；这只作用于这一次 curl，不会碰系统代理。正式版没有 `checksums.txt`，文件完整性靠 GitHub 的 TLS。

## 面板

上面是上下行速率和内核状态：是否在跑、端口、内存、连接数、分流模式、系统代理开没开。

中间三个独立开关面板：系统代理、分流模式、TUN。

主区域：

| 按键 | 页面 |
| --- | --- |
| `p` | 策略组和节点 |
| `c` | 当前连接 |
| `L` | 内核日志 |

代理订阅与分流方案位于设置的「订阅与分流」分类；DNS、规则、订阅源、片段、探测、运行时位于「排查」分类。

`s` 打开设置，`?` 打开快捷键说明。这两个页面按 `Esc` 都回到面板。

按 `q` 退出界面，后台内核继续跑。`Esc` 只返回，不会退出。要停止 terc 启动的内核，打开设置 → 代理 → 内核服务；其他客户端或服务管理器启动的内核，请到原处停止。启动失败原因会显示在浮动通知中，内核输出保存在配置目录的 `terc-core.log`。

不在节点页时，`Esc` 先回到节点页：规则页里如果正在过滤，第一次 `Esc` 先清掉过滤词。

## 机场订阅和订阅源不是一回事

**机场订阅**是机场发给你的那一条链接。下载时请求 gzip 压缩，单次最多等 60 秒，机场面板或订阅转换先花半分钟生成文件也能下完；前 20 秒内遇到 5xx、429 或超时会自动重试，最多两次，已经等满 60 秒的那次不再重试。在设置 → 代理订阅中更新订阅，与当前方案的手动节点一起生成配置目录里的 `config.yaml`，保留来源分流，验证通过后让内核热重载。没保存过链接时，先在设置中填写订阅地址。

**订阅源**是设置 → 排查打开的那一页，界面中文写「订阅源」，英文是 Providers。它对应配置里的两类东西：

- `proxy-providers`：节点列表的更新地址
- `rule-providers`：规则列表的更新地址

这是配置内部再去拉的源，不是你粘贴的那条机场链接。刷新订阅源不会换成另一个机场，也不会改 `config.json` 里的订阅链接。

在这一页：

- Enter：刷新当前这一条
- `F`：全部刷新
- `H`：只对代理源做健康检查。规则源没有延迟检查，按了会提示

`F` 每次同时刷新 4 个。更新订阅后配置没有变化、不需要重载时，terc 会改为通过控制器刷新 HTTP 类型的代理源（同样每次 4 个，跳过 `default` 和本地文件源），通知末尾写明成功和失败的个数；这样能拿到新节点，又不断开经代理源的连接。

订阅源和规则数据量大，后台刷新只在需要时读取：停在订阅源页时每次刷新都读订阅源，其他页面每 30 秒读一次（代理源节点的协议和延迟也来自这里）；规则只在规则页读取。内核刚启动或上一次刷新没连上内核时，下一次会全部重读。

## 订阅格式：Clash、Surge、节点列表都能用

在设置 → 代理订阅中更新订阅后，terc 自己判断格式，不用选：

| 订阅内容 | 怎么识别 | 怎么处理 |
| --- | --- | --- |
| Clash / Mihomo YAML | 有 `proxies:` 或 `proxy-providers:` | 节点和 DNS、TUN、端口等设置原样保留 |
| Surge 配置 | 有 `[Proxy]`、`[Proxy Group]`、`[Rule]` 段，或者就是一串 `名字 = ss, …` 行 | 逐条转成 Mihomo 的节点、策略组和规则 |
| 节点链接列表 | 一行一个 `ss://` `trojan://` `vless://` `vmess://` `hysteria2://`（`hy2://`） `tuic://` `anytls://` `socks5://`，明文或整体 base64 | 逐条转成节点 |

Surge 能转的：

- 节点：`ss`（含 `obfs`、`shadow-tls`、2022 加密）、`trojan`（含 ws）、`vmess`（含 ws、tls）、`http` / `https`、`socks5` / `socks5-tls`、`snell`（v1–v5，含 `reuse`、`obfs`、`shadow-tls`）、`hysteria2`、`tuic` / `tuic-v5`、`anytls`、`wireguard`（读取 `[WireGuard 名字]` 段：`private-key`、`self-ip` / `self-ip-v6`、`dns-server`、`mtu`、多个 `peer`，以及 peer 里的 `preshared-key`、`keepalive`、`client-id`）、`ssh`（密码，或 `[Keystore]` 里的私钥，`server-fingerprint` 会变成主机密钥校验）。`udp-relay`、`tfo`、`sni`、`skip-cert-verify`、`underlying-proxy` 一并带过去。
- 策略组：`select`、`url-test`、`fallback`、`load-balance`；`smart` 按 `url-test` 处理。`url`、`interval`、`tolerance`、`timeout`、`include-all-proxies`、`policy-regex-filter`、`include-other-group` 会对应过去。`url-test` 和 `smart` 没写 `tolerance` 时补 `tolerance: 50`：Mihomo 默认是 0，只要别的节点上一轮测速快 1 ms 就换节点，新连接的出口 IP 会跟着频繁变化。
- 规则：`DOMAIN` / `DOMAIN-SUFFIX` / `DOMAIN-KEYWORD` / `DOMAIN-WILDCARD`、`IP-CIDR` / `IP-CIDR6` / `IP-ASN`、`GEOIP`、`PROCESS-NAME`、端口类、`SRC-IP`、`PROTOCOL,TCP/UDP`、`AND` / `OR` / `NOT`、远程 `RULE-SET` 和 `DOMAIN-SET`（变成 Mihomo 的 rule-provider，缓存文件按链接区分；同一链接同一类型重复出现时共用一个），`FINAL` 变成 `MATCH`。

snell v4/v5 需要 Mihomo v1.19.26 或更新（`Ctrl+D` 下载的就是最新版）。v5 在 Mihomo 里按 v4 线协议连接，Surge 独有的 QUIC Proxy 模式没有。

转不了的会跳过，不会让整份配置失败：`external`、snell v6、只监听不连出去的 WireGuard 段（`listen-port` 且 peer 没有 `endpoint`）、`ssid` / `subnet` 策略组、`policy-path`、`USER-AGENT`、`URL-REGEX`、`RULE-SET,SYSTEM` / `LAN`、指向不存在策略的规则，以及 Mihomo 不支持的加密方式。更新完的通知里会写「跳过 N 项」，按 `!` 看清单。清单只写名字和类型，不会带出密码。

下载内容只有在能识别时才会存成缓存 `~/.config/terc/subscription.cache`；下坏了（比如机场返回网页）不会覆盖上一份好的。

## 代理订阅与分流方案

按 `s`，切到「订阅与分流」，直接看到代理列表；Tab 切换到分流列表。列表显示名称、类型、稳定编号与使用状态，选中行高亮。Esc 返回设置。

**添加代理**：在代理列表按 `a`，选择「订阅」「单个代理」或「导入链接 / 配置」。填写名称；订阅填写 URL，单个代理选择协议并填写服务器、端口、密码或 UUID、加密方式、TLS / SNI 等对应字段。支持 SS、Trojan、VMess、VLESS、SOCKS5、HTTP、Hysteria2、TUIC；其他已支持协议可通过链接导入。↑↓ / Tab 选择字段，←→ 切换选项，Enter 编辑，Ctrl+S 保存并使用。密码遮挡显示，长字段随光标滚动。

**WebSocket 与 HTTPUpgrade 节点**：VMess、VLESS、Trojan 的「传输」可在 TCP / WebSocket / HTTPUpgrade 之间切换。选 WebSocket 或 HTTPUpgrade 后填写路径和 Host 头（可选）；节点地址是 IP 或经 CDN 时，Host 填你的域名。VMess、VLESS 开启 TLS 且没填 SNI 时，Host 也用作 SNI；Trojan 不会这样做，经 CDN 时请同时填写 SNI。WebSocket 可填早期数据（字节数，可选），HTTPUpgrade 可开快速打开。保存时只改这几项，其他 `ws-opts`（例如自定义头、早期数据的头名）原样保留；只改名或改端口不会改变早期数据的方式。其他工具写出的 `network: httpupgrade` 在生成配置时会改写成 Mihomo 认识的 `network: ws` 加 `v2ray-http-upgrade: true`，通知里列出改写了哪些节点；原始订阅缓存不变。grpc、h2 等其他传输方式进入原始编辑器。

**管理代理**：Enter 使用选中项，`e` 编辑选中项，`n` 改名；`u` 更新当前订阅，`v` 管理当前来源的附加节点。保存失败保留原记录与当前配置。

**分流方案**：列表包括「跟随订阅分流」「全部代理」、各代理来源缓存的分流，以及你保存的命名方案。Enter 为当前代理指定方案，每个代理分别记住选择。`c` 将当前分流命名保存供其他代理复用。复用时节点来自当前代理来源，保留策略组间引用与过滤条件。

例如：机场 A 使用自带分流，自建节点 B 使用保存的「日常分流」。切换回 A 时恢复机场分流，切换回 B 时恢复「日常分流」。更新 B 的节点不会把 A 的节点带过来，也不会重置 B 选择的分流。

只有节点、没有自带规则的来源，默认使用一个选节点策略组和全部代理规则。原始订阅缓存单独保留。配置通过内核校验后才应用；失败时保留当前配置和分流选择。旧版本的本地快照仍可从分流列表选择，其节点不再覆盖当前代理订阅。自有规则编辑继续暂停。

## 常用设置

设置分为「代理」「外观」「订阅与分流」「排查」四类，用 Tab / Shift+Tab 或 1–4 切换。

代理设置包括混合 / HTTP / SOCKS 端口、允许局域网、TUN、DNS、IPv6、嗅探、TCP 并发、进程识别、测速地址和控制器超时。端口输入范围为 0–65535，0 关闭该监听；混合端口同时支持 HTTP 与 SOCKS，不要与另外两个监听重复。系统代理开启时，请先关闭再改端口，保存后重新开启。

进程识别有代价：Mihomo 在每个新连接拨号前同步查找发起它的进程，没有缓存。默认的 `strict` 只在规则检查走到 `PROCESS-NAME` 这类进程规则时查找；「进程名」片段（`find-process-mode: always`）让每个 TCP 连接和每个新 UDP 会话都查找。Linux 上一次查找实测约 1–15 ms：内核会扫描同一用户进程的 `/proc/*/fd`，打开的文件越多越慢，较晚启动的程序最慢（文件数更多时按每个约 1.6 µs 外推，可到 10–30 ms）；macOS 要读出整张 TCP 连接表，估计 0.3–2 ms，未实测。私有规则排在 AI 预设和订阅规则之前，所以一条 `PROCESS-NAME` 规则会让所有没被前面私有规则命中的连接（包括 AI 流量）都付这笔开销。能用域名规则时优先用域名规则；只想在连接页看到进程名时再开「进程名」片段。

外观设置包括主题、图表样式、界面刷新率、图表更新间隔、语言、顶部面板和底栏快捷键。图表更新间隔仅在设置中显示，主界面的速率图不再堆放毫秒标记。

界面刷新率是重绘的上限，不是固定帧率：按键和鼠标立即重绘（不超过这个频率），连接、速率等后台数据最多每 100 毫秒重绘一次，画面没有变化时只每秒重绘一次。调高它只让按键更跟手，空闲时不多占 CPU。

日志级别、内核下载、配置片段、连接探测、运行详情、规则浏览、远程资源与「连接实时推送」集中放在「排查」。启动失败会显示日志摘要；这里的日志也会读取 `terc-core.log`，上一轮启动日志保存在 `terc-core.previous.log`。新生成的配置把 `log-level` 设为 `warning`，`terc-core.log` 不再为每条新连接写一行；日志页始终按 info 订阅内核日志，显示的内容不变。订阅自带的 `log-level` 保持原样。控制器被占用或已有内核未响应时，terc 会拒绝重复启动；启动超时会回收这次新建的进程。

## 开关

TUN、嗅探、DNS、IPv6 和内核服务统一在设置 → 代理中调整。面板保留空格切换系统代理、`m` 切换分流模式。

## 嗅探

很多连接进内核时只有 IP，没有域名。规则如果按域名写，就对不上。

嗅探是 Mihomo 的 sniffer。它看流量开头的一小段：HTTP 的 Host、TLS 的 SNI、QUIC 里的名字，把域名补回去，后面的规则才能按域名匹配。连接列表里的嗅探域名就是这个结果。

它不保存网页内容，也不是系统抓包。在设置 → 代理中开关。

## DNS

从设置 → 排查打开 DNS 查询。左边是配置里的解析状态，右边可以查一个域名。

- `e` 进入输入，Enter 查询
- `[` 和 `]` 换记录类型
- `F` 清空 DNS 缓存和 Fake-IP 缓存
- 面板上的 `D` 开关 `dns.enable`

配置里没有 `dns` 块时，页面会提示。设置 → 排查 → 片段可以叠一份自带的 DNS 片段：

| 片段 | 解析 | 说明 |
| --- | --- | --- |
| Fake-IP DNS | `doh.pub`、`dns.alidns.com`（DoH），引导用 `223.5.5.5`、`119.29.29.29` | 与 terc 模板一致，适合中国大陆网络 |
| Fake-IP DNS（境外） | `dns.google`、`cloudflare-dns.com`（DoH），按分流规则连接（`respect-rules`） | 节点域名仍由国内 DoH 解析。直连模式下 DoH 也走直连，在中国大陆连不上，直连的域名会解析失败；大陆网络切直连前先关掉它 |

两份都只监听 `127.0.0.1:1053`，不对局域网开放；都不带 `fallback`；`fake-ip-filter` 默认排除 `*.lan`、`+.local`、`localhost`。片段里写到的列表会整体替换订阅原有的同名列表（比如 `nameserver`、`fallback`、`fake-ip-filter`），没写到的键保持订阅原样。TUN 的 DNS 劫持不依赖这个端口。

旧版的 Fake-IP DNS 片段用境外 DoH、带 fallback，并监听 `0.0.0.0:1053`。开着这个片段升级后，terc 首次启动会提示一次；新内容在下次生成配置时生效。想继续用境外 DoH，改开「Fake-IP DNS（境外）」即可。

## 规则

从设置 → 排查看规则顺序和命中次数。

- `/`：按类型、内容或策略搜索列表
- `e`：单独输入域名、IP 或 `process:名称`，测试匹配结果，不改变搜索条件
- Enter：查看所选规则的完整详情；宽窗口直接在右侧展示
- `x`：临时禁用或恢复当前规则
- `F`：向内核重新要一遍规则

GEOSITE 和规则集仍由内核先判断。界面解释的是已经展开的规则，对不上时会注明这一点。

GEOIP、GEOSITE、IP-ASN 规则用到的数据文件由内核首次需要时下载，每个文件只等 90 秒，下载失败时配置校验不通过。Mihomo 默认从 GitHub 下载；生成的配置里没有 `geox-url` 时，terc 会补上 jsDelivr 镜像（`testingcf.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/`，含 `geoip.dat`、`geosite.dat`、`country.mmdb`、`GeoLite2-ASN.mmdb`）。订阅自己写了 `geox-url` 时，哪怕只写了一项，也原样保留。

## 探测与片段

**探测**（设置 → 排查）：对当前选中的节点做 DNS 查询和延迟测试。输入域名或 URL，按 Enter。

macOS 开启 TUN 需要 Mihomo 拥有管理员权限。内核由 terc 启动时，按 `T` 会请求系统管理员授权；批准后重启内核并启用 TUN，现有连接会短暂中断。取消授权会保留原进程并恢复原配置。关闭 TUN 后内核仍以管理员权限运行，打开设置 → 代理 → 内核服务 停止时可能再次请求授权。如果内核尚未运行，`T` 只保存配置，之后 `K` 启动时请求授权。启动失败会显示 `Start TUN listening error`，按 `!` 看全文。手动启动且使用同一配置目录的本机 Mihomo，可以在核对端口、程序和配置参数后，经管理员授权由 terc 接管并重启。Homebrew/launchd 管理的服务应先在原服务停止，再按 K 由 terc 启动。

如果提示 `add route: 1.0.0.0/8: file exists`，先断开 Shadowrocket 等其他全流量 VPN，再开启 terc 的 TUN。terc 会提示已连接 VPN 与虚拟网卡路由冲突，不会删除其路由。系统代理的服务识别会跳过没有物理设备的 VPN 服务，查找当前连接的 Wi-Fi 或有线网络。

**片段**（`o`）：将一小段 YAML 合并到当前配置。自带的有 TUN、嗅探、Fake-IP DNS（国内与境外两份）、进程名、TCP 并发、IPv6。自己的文件可以放在 `~/.config/terc/modules`。映射递归合并，列表和标量整体替换；覆盖同名映射时使用多行块格式。原始配置保存在生成文件的注释中，关闭片段时还原。已手动调整的开关会保留。更新机场订阅或切换档案时会重新应用已启用片段。


所有候选配置先由 `mihomo -t` 验证，通过后再替换文件；热重载被拒绝时恢复旧配置。操作结果以浮动通知显示，普通通知 4 秒、错误通知 8 秒后自动收起；按 `!` 查看完整错误，Backspace 可提前收起。底部只保留一行快捷键；隐藏图表也能查看操作结果。

## 节点和连接

策略组在左边，节点在右边。`1` 和 `2`，或者 Tab、`h` / `l`，切换两边。`j` / `k` 或上下方向键移动。在节点上按 Enter 切换过去。

- `r`：给当前策略组做延迟测试
- `a`：选择全球优选或当前连接国家优选，重新测速后切换到范围内最低延迟节点。全球指当前策略组中所有国家的可选节点；国家根据已连接节点名称中的国旗、国家名或独立代码识别，无法识别时提示。此功能用于可手动切换的 Selector 策略组

连接页（`c`）：

- 每行显示时长，存活 60 秒以上的连接（长连接）时长加粗；访问 AI 服务（目标或嗅探域名命中 AI 预设规则，或经过 `AI` 策略组）的连接标 `AI`
- 列宽有限时按顺序显示：当前排序的数值（流量或速率合计）、进程、规则、上下行分开、入站；剩下的宽度给目标地址
- `o`：在按流量、按时长、按速率之间切换排序
- `f`：只看长连接和 AI 连接，再按一次显示全部
- `x`：断开当前一条；列表刷新后仍按连接 ID 保持选择，连接消失后需重新选择
- `X`：断开全部
- Enter：打开完整详情（进程、路径、入站、规则、链路、provider、时长、速率），窄窗口也可使用；上下键滚动，Esc 返回
- `d`：最近断开的长连接和 AI 连接（最多 50 条）。每条有断开多久、存活时长、流量和推断的原因；Enter 看完整一条，再按 `d` 回到连接列表

Mihomo 不提供断开原因，原因由 terc 根据自己的操作推断：在 terc 中断开、全部断开、内核停止或重启、配置重载（只算经订阅提供者节点的连接）、TUN 重建（只算经 TUN 进来的连接）。配置没有变化而没有重载时，不会算到重载头上。同一次刷新里有 3 条以上无故断开时，提示可能是网络切换、睡眠或节点故障。存活不到 10 秒、自己结束的 AI 请求不记录。AI 连接无故断开时弹出一次提示，30 秒内不重复。

全部断开、关闭 TUN、macOS 上需要重启内核的开启 TUN、停止内核，以及重载配置（切换配置或分流方案、「重载配置」、手动更新订阅、修改当前订阅地址、DNS 和片段开关）会断开长连接或 AI 连接时，先提示受影响的条数，6 秒内再按一次才执行。重载只统计经订阅提供者节点的连接；订阅内容没变时不会重载，所以提示写的是「可能断开」。能实时生效的设置（允许局域网、各端口、TCP 并发、进程识别、日志级别）直接下发，不重载，现有连接不受影响。

连接列表默认由内核通过 WebSocket 每秒推送一次；推送不可用时自动改回每 2.2 秒轮询一次，日志里写一行说明，恢复后再写一行。内核停止或重启造成的断开不写。设置 → 排查 →「连接实时推送」可以关掉推送，状态显示 `OFF`、`ON · WebSocket` 或 `ON · HTTP`（已开启但正在轮询）。控制器地址和密钥改了以后，需要重启 terc 才会用于推送。

日志页（`L`）：`P` 暂停/继续显示，后台仍保留最新 300 条日志；上下键选择历史日志，`/` 搜索，Enter 打开全文，上下键滚动，Esc 返回。帮助页（`?`）支持上下键、Page Up/Down 和 Home。

设置里：上下选择，左右或 Enter 执行，Tab / Shift+Tab 切换分类页，1 / 2 / 3 / 4 直接跳转（代理、外观、订阅与分流、排查）；上下键只在当前分类内移动。视觉与主题里可调整图表更新间隔（1000–86400000 毫秒，左右键每次调 100 ms，Enter 直接输入整数，Esc 取消），图中显示期间平均速率，顶部实时速率读数照常更新。改变间隔会清空旧图，避免混用不同时间尺度。

初始设置里：`Ctrl+U` 清空输入，`Ctrl+D` 下载内核，Enter 保存并启动，`Esc` 先关掉。

## Linux 和 macOS 的差别

其余操作两边一样：本机连 `127.0.0.1:9090`，用标准库 `TcpStream`；远端订阅和内核包用系统 `curl`。没有 tokio、reqwest、openssl。

**系统代理**

- macOS：用 `networksetup` 改当前网卡的 HTTP、HTTPS、SOCKS，指向 `127.0.0.1` 和内核端口。
- Linux：本机有 GNOME 的 `gsettings`，并且能读到 `org.gnome.system.proxy` 时，改成手动代理（HTTP、HTTPS、SOCKS）。没有这个组件就什么都不改，操作结果会说明。
- Linux 上不会调用 `networksetup`。
- 两边都不会自己打开系统代理。

**内核**

下载时按上一节的四张表选包。macOS 上如果用 Homebrew 安装过 mihomo，并且 `/opt/homebrew/etc/mihomo/config.yaml` 已经存在，配置目录会用那一处；否则用 `~/.config/terc/mihomo`。

界面与内核连接设置保存在 `~/.config/terc/config.json`。新存储按用途分开：

- `sources/<编号>/source.json`：名称、来源类型、订阅地址、结构化节点和分流选择。
- `sources/<编号>/subscription.yaml`：下载的原始订阅内容。
- `routing/`：可复用的命名分流方案。
- `generated/<编号>.yaml`：生成给内核使用的配置，不作为代理资料来源。

上述路径均位于 `~/.config/terc/`。新版启动时迁移旧资料，保留原来的 `profiles/`、`nodes.conf` 和缓存文件；不会删除旧数据。无名称的旧来源以订阅域名或编号命名。迁移不启停内核、不改变系统代理。
