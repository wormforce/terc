# terc 使用说明

`terc` 是 Mihomo（Clash.Meta）的终端控制器，支持 **macOS** 和 **Linux**。打开之后直接进入面板。已经有配置时，不会再经过启动菜单。

界面默认是简体中文。按 `s` 可以改成 English 或 日本語。

## 第一次打开

满足下面三条时，启动后先出现「初始设置」，而不是面板：

- 还没有保存机场订阅链接
- 本机 Mihomo 没在运行
- 配置目录里还没有 `config.yaml`

已经有其中任意一项，就直接进入面板。

初始设置做三件事：

1. 先确认 `mihomo` 内核已安装。没有的话按 `Ctrl+D`，从 GitHub 上的 MetaCubeX/mihomo 下载和这台机器匹配的包，放到 `~/.config/terc/core/mihomo`。
2. 粘贴机场给你的订阅链接，按 Enter。链接要以 `http://` 或 `https://` 开头，保存在本机 `~/.config/terc/config.json`；下载的配置会先由内核验证。没有机场也可以：直接粘贴一条自己的节点（Surge 节点行或 `ss://` 等链接，见「配置方案」），terc 会存进 `nodes.conf` 并生成配置。
3. 订阅写好、二进制也在，就会启动内核。

按 `Esc` 可以先关掉这个窗口。之后在面板上按 `u`：没填过订阅链接时会再打开。

系统代理不会在这一步打开。确认网络正常后，再在面板上按空格手动接管。

下载的内核包按本机选择，只有这四种：

| 系统 | CPU | 包名 |
| --- | --- | --- |
| macOS | Apple 芯片 | `mihomo-darwin-arm64` |
| macOS | Intel | `mihomo-darwin-amd64` |
| Linux | arm64 | `mihomo-linux-arm64` |
| Linux | x86_64 | `mihomo-linux-amd64` |

不提供 Windows 包。

## 面板

上面是上下行速率和内核状态：是否在跑、端口、内存、连接数、分流模式、系统代理开没开。

中间三个独立开关面板：系统代理、分流模式、TUN。

主区域：

| 按键 | 页面 |
| --- | --- |
| `p` | 策略组和节点 |
| `c` | 当前连接 |
| `L` | 内核日志 |
| `d` | DNS |
| `g` | 规则 |
| `v` | 订阅源（Providers） |

浮层：

| 按键 | 内容 |
| --- | --- |
| `o` | 片段 |
| `f` | 配置方案 |
| `b` | 探测 |
| `w` | 运行时：TUN 设备，以及 WireGuard / Tailscale 出站 |

`s` 打开设置，`?` 打开快捷键说明。这两个页面按 `Esc` 都回到面板。

按 `q` 退出界面，后台内核继续跑。`Esc` 只返回，不会退出。要停止 terc 启动的内核，按 `K`；其他客户端或服务管理器启动的内核，请到原处停止。启动失败原因会显示在浮动通知中，内核输出保存在配置目录的 `terc-core.log`。

不在节点页时，`Esc` 先回到节点页：规则页里如果正在过滤，第一次 `Esc` 先清掉过滤词。

## 机场订阅和订阅源不是一回事

**机场订阅**是机场发给你的那一条链接。按 `u` 下载，与当前方案的手动节点一起生成配置目录里的 `config.yaml`，保留来源分流，验证通过后让内核热重载。没保存过链接时，`u` 会打开初始设置。

**订阅源**是按 `v` 打开的那一页，界面中文写「订阅源」，英文是 Providers。它对应配置里的两类东西：

- `proxy-providers`：节点列表的更新地址
- `rule-providers`：规则列表的更新地址

这是配置内部再去拉的源，不是你粘贴的那条机场链接。刷新订阅源不会换成另一个机场，也不会改 `config.json` 里的订阅链接。

在这一页：

- Enter：刷新当前这一条
- `F`：全部刷新
- `H`：只对代理源做健康检查。规则源没有延迟检查，按了会提示

## 订阅格式：Clash、Surge、节点列表都能用

按 `u` 下载后，terc 自己判断格式，不用选：

| 订阅内容 | 怎么识别 | 怎么处理 |
| --- | --- | --- |
| Clash / Mihomo YAML | 有 `proxies:` 或 `proxy-providers:` | 节点和 DNS、TUN、端口等设置原样保留 |
| Surge 配置 | 有 `[Proxy]`、`[Proxy Group]`、`[Rule]` 段，或者就是一串 `名字 = ss, …` 行 | 逐条转成 Mihomo 的节点、策略组和规则 |
| 节点链接列表 | 一行一个 `ss://` `trojan://` `vless://` `vmess://` `hysteria2://`（`hy2://`） `tuic://` `anytls://` `socks5://`，明文或整体 base64 | 逐条转成节点 |

Surge 能转的：

- 节点：`ss`（含 `obfs`、`shadow-tls`、2022 加密）、`trojan`（含 ws）、`vmess`（含 ws、tls）、`http` / `https`、`socks5` / `socks5-tls`、`snell`（v1–v5，含 `reuse`、`obfs`、`shadow-tls`）、`hysteria2`、`tuic` / `tuic-v5`、`anytls`、`wireguard`（读取 `[WireGuard 名字]` 段：`private-key`、`self-ip` / `self-ip-v6`、`dns-server`、`mtu`、多个 `peer`，以及 peer 里的 `preshared-key`、`keepalive`、`client-id`）、`ssh`（密码，或 `[Keystore]` 里的私钥，`server-fingerprint` 会变成主机密钥校验）。`udp-relay`、`tfo`、`sni`、`skip-cert-verify`、`underlying-proxy` 一并带过去。
- 策略组：`select`、`url-test`、`fallback`、`load-balance`；`smart` 按 `url-test` 处理。`url`、`interval`、`tolerance`、`timeout`、`include-all-proxies`、`policy-regex-filter`、`include-other-group` 会对应过去。
- 规则：`DOMAIN` / `DOMAIN-SUFFIX` / `DOMAIN-KEYWORD` / `DOMAIN-WILDCARD`、`IP-CIDR` / `IP-CIDR6` / `IP-ASN`、`GEOIP`、`PROCESS-NAME`、端口类、`SRC-IP`、`PROTOCOL,TCP/UDP`、`AND` / `OR` / `NOT`、远程 `RULE-SET` 和 `DOMAIN-SET`（变成 Mihomo 的 rule-provider），`FINAL` 变成 `MATCH`。

snell v4/v5 需要 Mihomo v1.19.26 或更新（`Ctrl+D` 下载的就是最新版）。v5 在 Mihomo 里按 v4 线协议连接，Surge 独有的 QUIC Proxy 模式没有。

转不了的会跳过，不会让整份配置失败：`external`、snell v6、只监听不连出去的 WireGuard 段（`listen-port` 且 peer 没有 `endpoint`）、`ssid` / `subnet` 策略组、`policy-path`、`USER-AGENT`、`URL-REGEX`、`RULE-SET,SYSTEM` / `LAN`、指向不存在策略的规则，以及 Mihomo 不支持的加密方式。更新完的通知里会写「跳过 N 项」，按 `!` 看清单。清单只写名字和类型，不会带出密码。

下载内容只有在能识别时才会存成缓存 `~/.config/terc/subscription.cache`；下坏了（比如机场返回网页）不会覆盖上一份好的。

## 配置方案：订阅与手动节点统一管理

按 `s`，切到「配置方案」，Enter 打开方案管理；面板上的 `f` 也可以打开。订阅、VPS、自建节点都归在同一个方案里管理，不再分散到独立入口。

- **方案列表**：`a` 粘贴订阅地址或节点创建新方案（支持多行与整段 WireGuard 配置）；`c` 保存当前方案的副本；`n` 重命名；Enter 应用选中的方案。
- **当前订阅**：`e` 编辑来源，`u` 更新。要添加另一家机场，请在方案列表按 `a`，这样可以随时切回来。
- **手动节点**：`a` 添加，`d` 删除，`r` / Enter 测速，`A` 全部测速。支持 Surge 节点行和 ss / trojan / vmess / vless / hysteria2 / tuic / wireguard / ssh 等链接。

Tab / Shift+Tab 或 1 / 2 / 3 切换方案管理页；Esc 回到设置。每个方案分别保存订阅缓存、节点和来源信息，切换方案后更新订阅不会混入上一个方案。保存后的配置快照位于 `~/.config/terc/profiles/<id>.yaml`，来源与节点位于同名目录内；密码不会显示在节点列表中。

Clash 与可转换的 Surge 订阅优先保留来源自带的策略组、规则和规则集。手动节点加入可手动选择的组；只有节点而没有完整分流时，生成一个 `PROXY` 选择组和 `MATCH` 兜底规则。

**自有规则与 AI 预设的开发、编辑入口暂缓。** 原有 `rules.conf` 保留在本机；新生成配置不再叠加其中的自有规则、国内直连或 AI 预设，也不会额外制造 AUTO / AI 策略组。已有生效配置在更新或重新生成前保持原状。

## 常用设置

设置分为「代理」「外观」「配置方案」「排查」四类，用 Tab / Shift+Tab 或 1–4 切换。

代理设置包括混合 / HTTP / SOCKS 端口、允许局域网、TUN、DNS、IPv6、嗅探、TCP 并发、进程识别、测速地址和控制器超时。端口输入范围为 0–65535，0 关闭该监听；混合端口同时支持 HTTP 与 SOCKS，不要与另外两个监听重复。系统代理开启时，请先关闭再改端口，保存后重新开启。

外观设置包括主题、图表样式、界面刷新率、图表更新间隔、语言、顶部面板和底栏快捷键。图表更新间隔仅在设置中显示，主界面的速率图不再堆放毫秒标记。

日志级别、内核下载、配置片段、连接探测、运行详情、规则浏览与远程资源集中放在「排查」。启动失败会显示日志摘要；这里的日志也会读取 `terc-core.log`，上一轮启动日志保存在 `terc-core.previous.log`。控制器被占用或已有内核未响应时，terc 会拒绝重复启动；启动超时会回收这次新建的进程。

## 开关

这些键在面板上直接生效，并写回配置。

| 按键 | 作用 |
| --- | --- |
| `T` | TUN。用虚拟网卡接管流量 |
| `n` | 嗅探。见下一节 |
| 空格 | 系统代理。只有按下时才改 |
| `D` | 配置里的 `dns.enable`，然后热重载 |
| `i` | 是否解析 IPv6（AAAA） |
| `m` | 分流模式在 Rule、Global、Direct 之间切换 |
| `K` | 启动或停止后台 mihomo |

## 嗅探

很多连接进内核时只有 IP，没有域名。规则如果按域名写，就对不上。

嗅探是 Mihomo 的 sniffer。它看流量开头的一小段：HTTP 的 Host、TLS 的 SNI、QUIC 里的名字，把域名补回去，后面的规则才能按域名匹配。连接列表里的嗅探域名就是这个结果。

它不保存网页内容，也不是系统抓包。按 `n` 开关。

## DNS

按 `d` 打开 DNS 页。左边是配置里的解析状态，右边可以查一个域名。

- `e` 进入输入，Enter 查询
- `[` 和 `]` 换记录类型
- `F` 清空 DNS 缓存和 Fake-IP 缓存
- 面板上的 `D` 开关 `dns.enable`

配置里没有 `dns` 块时，页面会提示。按 `o` 可以叠一份自带的 Fake-IP DNS 片段。

## 规则

按 `g` 看规则顺序和命中次数。

- `/`：按类型、内容或策略搜索列表
- `e`：单独输入域名、IP 或 `process:名称`，测试匹配结果，不改变搜索条件
- Enter：查看所选规则的完整详情；宽窗口直接在右侧展示
- `x`：临时禁用或恢复当前规则
- `F`：向内核重新要一遍规则

GEOSITE 和规则集仍由内核先判断。界面解释的是已经展开的规则，对不上时会注明这一点。

## 探测、片段、配置方案

**探测**（`b`）：对当前选中的节点做 DNS 查询和延迟测试。输入域名或 URL，按 Enter。

macOS 开启 TUN 需要 Mihomo 拥有管理员权限。内核由 terc 启动时，按 `T` 会请求系统管理员授权；批准后重启内核并启用 TUN，现有连接会短暂中断。取消授权会保留原进程并恢复原配置。关闭 TUN 后内核仍以管理员权限运行，按 `K` 停止时可能再次请求授权。如果内核尚未运行，`T` 只保存配置，之后 `K` 启动时请求授权。启动失败会显示 `Start TUN listening error`，按 `!` 看全文。手动启动且使用同一配置目录的本机 Mihomo，可以在核对端口、程序和配置参数后，经管理员授权由 terc 接管并重启。Homebrew/launchd 管理的服务应先在原服务停止，再按 K 由 terc 启动。

如果提示 `add route: 1.0.0.0/8: file exists`，先断开 Shadowrocket 等其他全流量 VPN，再开启 terc 的 TUN。terc 会提示已连接 VPN 与虚拟网卡路由冲突，不会删除其路由。系统代理的服务识别会跳过没有物理设备的 VPN 服务，查找当前连接的 Wi-Fi 或有线网络。

**片段**（`o`）：将一小段 YAML 合并到当前配置。自带的有 TUN、嗅探、Fake-IP、进程名、TCP 并发、IPv6。自己的文件可以放在 `~/.config/terc/modules`。映射递归合并，列表和标量整体替换；覆盖同名映射时使用多行块格式。原始配置保存在生成文件的注释中，关闭片段时还原。已手动调整的开关会保留。更新机场订阅或切换档案时会重新应用已启用片段。

**配置方案**（`f`）：统一管理订阅与手动节点，见上文。Enter 应用选中方案，`c` 保存副本，`n` 重命名。

所有候选配置先由 `mihomo -t` 验证，通过后再替换文件；热重载被拒绝时恢复旧配置。操作结果以浮动通知显示，普通通知 4 秒、错误通知 8 秒后自动收起；按 `!` 查看完整错误，Backspace 可提前收起。底部只保留一行快捷键；隐藏图表也能查看操作结果。

## 节点和连接

策略组在左边，节点在右边。`1` 和 `2`，或者 Tab、`h` / `l`，切换两边。`j` / `k` 或上下方向键移动。在节点上按 Enter 切换过去。

- `r`：给当前策略组做延迟测试
- `a`：选择全球优选或当前连接国家优选，重新测速后切换到范围内最低延迟节点。全球指当前策略组中所有国家的可选节点；国家根据已连接节点名称中的国旗、国家名或独立代码识别，无法识别时提示。此功能用于可手动切换的 Selector 策略组

连接页（`c`）：

- `x`：断开当前一条；列表刷新后仍按连接 ID 保持选择，连接消失后需重新选择
- `X`：断开全部
- Enter：打开完整详情，窄窗口也可使用；上下键滚动，Esc 返回

日志页（`L`）：`P` 暂停/继续显示，后台仍保留最新 300 条日志；上下键选择历史日志，`/` 搜索，Enter 打开全文，上下键滚动，Esc 返回。帮助页（`?`）支持上下键、Page Up/Down 和 Home。

## Linux 和 macOS 的差别

其余操作两边一样：本机连 `127.0.0.1:9090`，用标准库 `TcpStream`；远端订阅和内核包用系统 `curl`。没有 tokio、reqwest、openssl。

**系统代理**

- macOS：用 `networksetup` 改当前网卡的 HTTP、HTTPS、SOCKS，指向 `127.0.0.1` 和内核端口。
- Linux：本机有 GNOME 的 `gsettings`，并且能读到 `org.gnome.system.proxy` 时，改成手动代理（HTTP、HTTPS、SOCKS）。没有这个组件就什么都不改，操作结果会说明。
- Linux 上不会调用 `networksetup`。
- 两边都不会自己打开系统代理。

**内核**

下载时按上一节的四张表选包。macOS 上如果用 Homebrew 安装过 mihomo，并且 `/opt/homebrew/etc/mihomo/config.yaml` 已经存在，配置目录会用那一处；否则用 `~/.config/terc/mihomo`。

界面设置保存在 `~/.config/terc/config.json`。已保存方案的节点、订阅缓存和来源信息在 `~/.config/terc/profiles/<id>/`。旧版 `rules.conf` 保留但不再参与新配置的生成。
