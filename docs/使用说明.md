# terc 使用说明

`terc` 是 Mihomo（Clash.Meta）的终端控制器，支持 **macOS** 和 **Linux**。打开之后直接进入面板。已经有配置时，不会再经过启动菜单。

界面默认是简体中文。按 `s` 可以改成 English 或 日本語。

## 第一次打开

满足下面三条时，启动后先出现「初始设置」，而不是面板：

- 还没有保存机场订阅链接
- 本机 Mihomo 没在运行
- 配置目录里还没有 `config.yaml`

已经有其中任意一项，就直接进入面板。

初始设置做三件事：

1. 先确认 `mihomo` 内核已安装。没有的话按 `Ctrl+D`，从 GitHub 上的 MetaCubeX/mihomo 下载和这台机器匹配的包，放到 `~/.config/terc/core/mihomo`。
2. 粘贴机场给你的订阅链接，按 Enter。链接要以 `http://` 或 `https://` 开头，保存在本机 `~/.config/terc/config.json`；下载的配置会先由内核验证。没有机场也可以：直接粘贴一条自己的节点（Surge 节点行或 `ss://` 等链接，见「自有节点」），terc 会存进 `nodes.conf` 并生成配置。
3. 订阅写好、二进制也在，就会启动内核。

按 `Esc` 可以先关掉这个窗口。之后在面板上按 `u`：没填过订阅链接时会再打开。

系统代理不会在这一步打开。确认网络正常后，再在面板上按空格手动接管。

下载的内核包按本机选择，只有这四种：

| 系统 | CPU | 包名 |
| --- | --- | --- |
| macOS | Apple 芯片 | `mihomo-darwin-arm64` |
| macOS | Intel | `mihomo-darwin-amd64` |
| Linux | arm64 | `mihomo-linux-arm64` |
| Linux | x86_64 | `mihomo-linux-amd64` |

不提供 Windows 包。

## 面板

上面是上下行速率和内核状态：是否在跑、端口、内存、连接数、分流模式、系统代理开没开。

中间三个独立开关面板：系统代理、分流模式、TUN。

主区域：

| 按键 | 页面 |
| --- | --- |
| `p` | 策略组和节点 |
| `c` | 当前连接 |
| `L` | 内核日志 |
| `d` | DNS |
| `g` | 规则 |
| `v` | 订阅源（Providers） |

浮层：

| 按键 | 内容 |
| --- | --- |
| `o` | 片段 |
| `f` | 配置档案 |
| `b` | 探测 |
| `w` | 运行时：TUN 设备，以及 WireGuard / Tailscale 出站 |

`s` 打开设置，`?` 打开快捷键说明。这两个页面按 `Esc` 都回到面板。

按 `q` 退出界面，后台内核继续跑。`Esc` 只返回，不会退出。要停止 terc 启动的内核，按 `K`；其他客户端或服务管理器启动的内核，请到原处停止。启动失败原因会显示在浮动通知中，内核输出保存在配置目录的 `terc-core.log`。

不在节点页时，`Esc` 先回到节点页：规则页里如果正在过滤，第一次 `Esc` 先清掉过滤词。

## 机场订阅和订阅源不是一回事

**机场订阅**是机场发给你的那一条链接。按 `u` 下载，和自有节点、私有规则一起合成配置目录里的 `config.yaml`（见下一节），验证通过后让内核热重载。没保存过链接时，`u` 会打开初始设置。

**订阅源**是按 `v` 打开的那一页，界面中文写「订阅源」，英文是 Providers。它对应配置里的两类东西：

- `proxy-providers`：节点列表的更新地址
- `rule-providers`：规则列表的更新地址

这是配置内部再去拉的源，不是你粘贴的那条机场链接。刷新订阅源不会换成另一个机场，也不会改 `config.json` 里的订阅链接。

在这一页：

- Enter：刷新当前这一条
- `F`：全部刷新
- `H`：只对代理源做健康检查。规则源没有延迟检查，按了会提示

## 订阅格式：Clash、Surge、节点列表都能用

按 `u` 下载后，terc 自己判断格式，不用选：

| 订阅内容 | 怎么识别 | 怎么处理 |
| --- | --- | --- |
| Clash / Mihomo YAML | 有 `proxies:` 或 `proxy-providers:` | 节点和 DNS、TUN、端口等设置原样保留 |
| Surge 配置 | 有 `[Proxy]`、`[Proxy Group]`、`[Rule]` 段，或者就是一串 `名字 = ss, …` 行 | 逐条转成 Mihomo 的节点、策略组和规则 |
| 节点链接列表 | 一行一个 `ss://` `trojan://` `vless://` `vmess://` `hysteria2://`（`hy2://`） `tuic://` `anytls://` `socks5://`，明文或整体 base64 | 逐条转成节点 |

Surge 能转的：

- 节点：`ss`（含 `obfs`、`shadow-tls`、2022 加密）、`trojan`（含 ws）、`vmess`（含 ws、tls）、`http` / `https`、`socks5` / `socks5-tls`、`snell`（v1–v3）、`hysteria2`、`tuic` / `tuic-v5`、`anytls`。`udp-relay`、`tfo`、`sni`、`skip-cert-verify`、`underlying-proxy` 一并带过去。
- 策略组：`select`、`url-test`、`fallback`、`load-balance`；`smart` 按 `url-test` 处理。`url`、`interval`、`tolerance`、`timeout`、`include-all-proxies`、`policy-regex-filter`、`include-other-group` 会对应过去。
- 规则：`DOMAIN` / `DOMAIN-SUFFIX` / `DOMAIN-KEYWORD` / `DOMAIN-WILDCARD`、`IP-CIDR` / `IP-CIDR6` / `IP-ASN`、`GEOIP`、`PROCESS-NAME`、端口类、`SRC-IP`、`PROTOCOL,TCP/UDP`、`AND` / `OR` / `NOT`、远程 `RULE-SET` 和 `DOMAIN-SET`（变成 Mihomo 的 rule-provider），`FINAL` 变成 `MATCH`。

转不了的会跳过，不会让整份配置失败：`wireguard`、`ssh`、`external`、snell v4/v5、`ssid` / `subnet` 策略组、`policy-path`、`USER-AGENT`、`URL-REGEX`、`RULE-SET,SYSTEM` / `LAN`、指向不存在策略的规则，以及 Mihomo 不支持的加密方式。更新完的通知里会写「跳过 N 项」，按 `!` 看清单。清单只写名字和类型，不会带出密码。

下载内容只有在能识别时才会存成缓存 `~/.config/terc/subscription.cache`；下坏了（比如机场返回网页）不会覆盖上一份好的。

## terc 自己生成配置

以前 `u` 是把机场的 YAML 原样当配置用。现在 `config.yaml` 由 terc 合成，三样东西拼起来：

1. **订阅节点**：上一节转出来的节点（Clash 订阅还会保留它的 DNS、TUN、端口、`proxy-providers` 等设置）。
2. **自有节点**：`~/.config/terc/nodes.conf` 里你自己的 VPS。
3. **terc 的规则**：私有规则 + AI 预设 + 局域网直连 + 国内直连，最后 `MATCH,PROXY`。机场自带的策略组和规则默认**不用**。

terc 生成的策略组：

| 组 | 类型 | 内容 |
| --- | --- | --- |
| `PROXY` | 手动选择 | `AUTO`、`AI`、全部节点、`DIRECT`。没被规则命中的流量都走这里 |
| `AUTO` | 自动测速 | 全部节点，挑延迟最低的 |
| `AI` | 自动测速（可改成故障转移） | 只放美国、日本、新加坡、台湾节点，排除香港，见「私有规则与 AI 分流」 |

「剩余流量」「到期时间」这类信息节点不会进组。如果机场或你的节点里已经有叫 `PROXY` / `AUTO` / `AI` 的名字，terc 的组会改名成 `terc-PROXY` 等，规则里写 `PROXY` 仍然指向它。

每次重新生成都会先跑 `mihomo -t`，通过才替换文件，再热重载；失败就保留旧配置。你用 `T`、`n`、`i`、`D` 改过的 TUN、嗅探、IPv6、DNS 开关，以及 `o` 里启用的片段，重新生成后都还在。

`config.yaml` 第一行写着 `# terc-generated`，不要手改它，下次生成会被覆盖。要改就改下面两个文件。

## 私有规则与 AI 分流（R）

在面板上按 `R`。上半部分是设置，下半部分是你的规则列表。每改一次都会写进 `~/.config/terc/rules.conf`，然后自动重新生成配置并热重载。

| 按键 | 作用 |
| --- | --- |
| `a` | 新增一条规则（插到当前选中行的下面） |
| `d` / Delete | 删除当前规则 |
| `J` / `K`，或 Shift+↓ / Shift+↑ | 把当前规则下移 / 上移。越靠上越先匹配 |
| `t` | 切换目标：`PROXY` → `AI` → `AUTO` → `DIRECT` → `REJECT` |
| `p` | 开关 AI 预设 |
| `y` | AI 组在「自动测速」(`url-test`) 和「故障转移」(`fallback`) 之间切换 |
| `m` | 选择 AI 组的成员（见下） |
| `b` | 是否追加机场自带的策略组和规则 |
| `c` | 是否国内直连（`DOMAIN-SUFFIX,cn` 和 `GEOIP,CN`） |
| Enter | 重新读 `rules.conf` 并应用（手改文件后用） |
| Esc / `q` / `R` | 关闭 |

新增规则时输入 `类型,内容,目标`，例如：

- `DOMAIN-SUFFIX,example.com,AI`
- `DOMAIN-KEYWORD,steam,DIRECT`
- `IP-CIDR,10.8.0.0/16,DIRECT`（IP 规则会自动加 `no-resolve`）
- `GEOIP,JP,AUTO`
- `PROCESS-NAME,Cursor,AI`

也可以偷懒：只写 `example.com` 等于 `DOMAIN-SUFFIX,example.com,PROXY`；写 `example.com,DIRECT` 只换目标。类型可以简写成 `suffix`、`keyword`、`domain`、`ip`、`geoip`、`process`。目标除了 `PROXY` `AI` `AUTO` `DIRECT` `REJECT`，也可以写任意节点名或策略组名；写了不存在的名字，这条会被跳过并在通知里说明。

**匹配顺序**：私有规则 → AI 预设 → 局域网直连 → 机场规则（打开 `b` 时）→ 国内直连 → `MATCH,PROXY`。所以你的规则永远优先，可以用来覆盖 AI 预设，比如把某个 AI 网站改成 `DIRECT`。

**AI 预设**把下面这些服务送进 `AI` 组：

| 服务 | 域名 |
| --- | --- |
| OpenAI / ChatGPT / Sora | openai.com、chatgpt.com、chat.com、oaistatic.com、oaiusercontent.com、sora.com、chatgpt.livekit.cloud，以及含 `openai` 的域名 |
| Anthropic / Claude | anthropic.com、claude.ai、claude.com、claudeusercontent.com |
| Google Gemini / AI Studio / NotebookLM | gemini.google.com、aistudio.google.com、ai.google.dev、generativelanguage.googleapis.com、notebooklm.google、deepmind 等 |
| xAI / Grok | x.ai、grok.com |
| Perplexity | perplexity.ai、pplx.ai |
| Cursor | cursor.com、cursor.sh、cursorapi.com、cursor-cdn.com |
| GitHub Copilot | githubcopilot.com、copilot-proxy / origin-tracker / copilot-telemetry.githubusercontent.com |
| Microsoft Copilot / Bing | copilot.microsoft.com、copilot.cloud.microsoft、bing.com、bingapis.com |
| Midjourney、Hugging Face、Poe | midjourney.com；huggingface.co、hf.co、hf.space；poe.com、poecdn.net |
| 其他 | meta.ai、mistral.ai、cohere、groq.com、openrouter.ai、together.ai、replicate.com、windsurf.com、codeium.com、v0.dev、character.ai、suno、elevenlabs.io、runwayml.com |

完整列表在源码 `src/compose.rs` 的 `AI_PRESET` 里。`github.com` 本身不在里面，只有 Copilot 的接口域名。

**AI 组选哪些节点**：默认自动挑，按节点名匹配美国、日本、新加坡、台湾（国旗、中文名、`US` `JP` `SG` `TW`、常见城市名），排除香港和信息节点。这些 AI 服务对香港、中国大陆 IP 限制最多。机场换了节点名也能自动跟上。

想自己指定，按 `m`：列表里是当前内核里的策略组和节点，加上你的自有节点。空格选中或取消，`c` 清空（等于回到自动挑），Enter 保存。选了的话 AI 组只用这些。

**手改 `rules.conf`**：文件分三段。

```ini
[ai]
enabled = true
type = url-test            # 或 fallback
members =                  # 留空 = 自动；指定时用 | 分隔，如  🇯🇵 东京 01 | 🇺🇸 美西 02 | AUTO
filter = (?i)(🇺🇸|🇯🇵|…)   # 自动挑选时的正则，可改
exclude = (?i)(🇭🇰|港|…)    # 排除的正则

[options]
subscription-rules = false # 追加机场规则
cn-direct = true           # 国内直连

[rules]
DOMAIN-SUFFIX,example.com,AI
PROCESS-NAME,Telegram,PROXY
```

`[rules]` 里可以写任何 Mihomo 支持的规则（TUI 里只提供常用的几种）。改完回 terc 按 `R` 再按 Enter 应用。通过 TUI 修改时，terc 会按标准格式重写这个文件，`[rules]` 中间的注释不会保留。

## 自有节点 / VPS（N）

自己买的 VPS，不需要机场也能用。在面板上按 `N`：

| 按键 | 作用 |
| --- | --- |
| `a` | 粘贴一条节点，Enter 添加。一次粘贴多行就一次加多个 |
| `d` / Delete | 删除当前节点 |
| `r` / Enter | 测当前节点延迟（内核要在运行） |
| `A` | 测全部自有节点 |
| Esc / `q` / `N` | 关闭 |

支持两种写法：

- Surge 节点行：`🇺🇸 我的VPS = ss, 1.2.3.4, 8388, encrypt-method=2022-blake3-aes-128-gcm, password=…, udp-relay=true, tfo=true`
- 链接：`ss://` `trojan://` `vless://`（含 Reality） `vmess://` `hysteria2://` `tuic://` `anytls://` `socks5://` `http(s)://`

添加后会马上校验：加密方式 Mihomo 不支持、SS2022 密钥长度不对、端口不对，都会直接提示，不会写进去。

节点存在 `~/.config/terc/nodes.conf`，一行一个，文件权限 600，只在本机，不上传。也可以直接编辑这个文件，`#` 开头是注释，改完回 terc 按 `R` 再按 Enter（或按 `u`）重新生成。

列表里只显示名字、协议和服务器地址，不显示密码；通知和日志也不会带出密码。

自有节点和订阅节点一样，会进 `PROXY` 和 `AUTO`；名字像美/日/新/台的，也会自动进 `AI`。和订阅节点重名时会自动改名成 `名字 (2)`。节点页（`p`）里选 `PROXY` 组就能切到它，`r` 可以和其他节点一起测速。

只有自有节点、没有机场订阅也可以：初始设置里直接粘贴节点就行。

## 开关

这些键在面板上直接生效，并写回配置。

| 按键 | 作用 |
| --- | --- |
| `T` | TUN。用虚拟网卡接管流量 |
| `n` | 嗅探。见下一节 |
| 空格 | 系统代理。只有按下时才改 |
| `D` | 配置里的 `dns.enable`，然后热重载 |
| `i` | 是否解析 IPv6（AAAA） |
| `m` | 分流模式在 Rule、Global、Direct 之间切换 |
| `K` | 启动或停止后台 mihomo |

## 嗅探

很多连接进内核时只有 IP，没有域名。规则如果按域名写，就对不上。

嗅探是 Mihomo 的 sniffer。它看流量开头的一小段：HTTP 的 Host、TLS 的 SNI、QUIC 里的名字，把域名补回去，后面的规则才能按域名匹配。连接列表里的嗅探域名就是这个结果。

它不保存网页内容，也不是系统抓包。按 `n` 开关。

## DNS

按 `d` 打开 DNS 页。左边是配置里的解析状态，右边可以查一个域名。

- `e` 进入输入，Enter 查询
- `[` 和 `]` 换记录类型
- `F` 清空 DNS 缓存和 Fake-IP 缓存
- 面板上的 `D` 开关 `dns.enable`

配置里没有 `dns` 块时，页面会提示。按 `o` 可以叠一份自带的 Fake-IP DNS 片段。

## 规则

按 `g` 看规则顺序和命中次数。

- `/` 或 `e`：输入域名、IP，或 `process:名称`，过滤列表，并解释会命中哪条
- `x`：临时禁用或恢复当前规则
- `F`：向内核重新要一遍规则

GEOSITE 和规则集仍由内核先判断。界面解释的是已经展开的规则，对不上时会注明这一点。

## 探测、片段、配置档案

**探测**（`b`）：对当前选中的节点做 DNS 查询和延迟测试。输入域名或 URL，按 Enter。

macOS 开启 TUN 需要 Mihomo 拥有管理员权限。内核由 terc 启动时，按 `T` 会请求系统管理员授权；批准后重启内核并启用 TUN，现有连接会短暂中断。取消授权会保留原进程并恢复原配置。关闭 TUN 后内核仍以管理员权限运行，按 `K` 停止时可能再次请求授权。如果内核尚未运行，`T` 只保存配置，之后 `K` 启动时请求授权。启动失败会显示 `Start TUN listening error`，按 `!` 看全文。手动启动且使用同一配置目录的本机 Mihomo，可以在核对端口、程序和配置参数后，经管理员授权由 terc 接管并重启。Homebrew/launchd 管理的服务应先在原服务停止，再按 K 由 terc 启动。

如果提示 `add route: 1.0.0.0/8: file exists`，先断开 Shadowrocket 等其他全流量 VPN，再开启 terc 的 TUN。terc 会提示已连接 VPN 与虚拟网卡路由冲突，不会删除其路由。系统代理的服务识别会跳过没有物理设备的 VPN 服务，查找当前连接的 Wi-Fi 或有线网络。

**片段**（`o`）：将一小段 YAML 合并到当前配置。自带的有 TUN、嗅探、Fake-IP、进程名、TCP 并发、IPv6。自己的文件可以放在 `~/.config/terc/modules`。映射递归合并，列表和标量整体替换；覆盖同名映射时使用多行块格式。原始配置保存在生成文件的注释中，关闭片段时还原。已手动调整的开关会保留。更新机场订阅或切换档案时会重新应用已启用片段。

**配置档案**（`f`）：配置目录和 `~/.config/terc/profiles` 里的其他 YAML。Enter 把它写成当前 `config.yaml` 并热重载。`c` 把当前配置存一份副本。`r` 再载入一次。

所有候选配置先由 `mihomo -t` 验证，通过后再替换文件；热重载被拒绝时恢复旧配置。操作结果以浮动通知显示，普通通知 4 秒、错误通知 8 秒后自动收起；按 `!` 查看完整错误，Backspace 可提前收起。底部只保留一行快捷键；隐藏图表也能查看操作结果。

## 节点和连接

策略组在左边，节点在右边。`1` 和 `2`，或者 Tab、`h` / `l`，切换两边。`j` / `k` 或上下方向键移动。在节点上按 Enter 切换过去。

- `r`：给当前策略组做延迟测试
- `a`：选择全球优选或当前连接国家优选，重新测速后切换到范围内最低延迟节点。全球指当前策略组中所有国家的可选节点；国家根据已连接节点名称中的国旗、国家名或独立代码识别，无法识别时提示。此功能用于可手动切换的 Selector 策略组

连接页（`c`）：

- `x`：断开当前一条；列表刷新后仍按连接 ID 保持选择，连接消失后需重新选择
- `X`：断开全部
- Enter：打开完整详情，窄窗口也可使用；上下键滚动，Esc 返回

日志页（`L`）：`P` 暂停/继续显示，后台仍保留最新 300 条日志；上下键选择历史日志，`/` 搜索，Enter 打开全文，上下键滚动，Esc 返回。帮助页（`?`）支持上下键、Page Up/Down 和 Home。

## Linux 和 macOS 的差别

其余操作两边一样：本机连 `127.0.0.1:9090`，用标准库 `TcpStream`；远端订阅和内核包用系统 `curl`。没有 tokio、reqwest、openssl。

**系统代理**

- macOS：用 `networksetup` 改当前网卡的 HTTP、HTTPS、SOCKS，指向 `127.0.0.1` 和内核端口。
- Linux：本机有 GNOME 的 `gsettings`，并且能读到 `org.gnome.system.proxy` 时，改成手动代理（HTTP、HTTPS、SOCKS）。没有这个组件就什么都不改，操作结果会说明。
- Linux 上不会调用 `networksetup`。
- 两边都不会自己打开系统代理。

**内核**

下载时按上一节的四张表选包。macOS 上如果用 Homebrew 安装过 mihomo，并且 `/opt/homebrew/etc/mihomo/config.yaml` 已经存在，配置目录会用那一处；否则用 `~/.config/terc/mihomo`。

界面设置保存在 `~/.config/terc/config.json`。私有规则在 `rules.conf`，自有节点在 `nodes.conf`，订阅缓存在 `subscription.cache`，都在 `~/.config/terc/` 下。
